# 0008 — Observation identity, revisions, and value representation

Status: accepted (milestone 03.2, #35)

## Context

Milestone 03 stored observations with a random `id` and deduplicated on a
connector-supplied `source_identity` with `ON CONFLICT DO NOTHING`. Three
problems surfaced before any production data existed:

- **Revisions were lost.** Providers such as Vercel, App Store Connect, and
  Search Console revise recent days as late data arrives. The first value
  ingested for a day stayed forever.
- **The table could not be partitioned by time.** PostgreSQL requires every
  unique key of a partitioned table to include the partition column. Neither
  the random `id` nor `(connection_id, source_identity)` did.
- **Series had no identity.** Grouping by dimension needed jsonb scans, and
  deduplication depended on each connector inventing a consistent string.

## Decision

- **Identity.** An observation is identified by `(connection_id,
metric_definition_id, series_key, source_timestamp)`, which is also the
  primary key. `series_key` is a stored column generated by the database as
  `md5(dimensions::text)`. jsonb normalizes key order, so equal dimension
  sets always produce the same key, and no application code computes it. The
  connector SDK drops `sourceIdentity` and exposes `observationKey()`, the
  same identity for contract tests and batch deduplication.
- **Revisions.** Ingestion upserts: `ON CONFLICT (…) DO UPDATE SET value,
ingested_at WHERE value IS DISTINCT FROM excluded.value`. A changed value
  replaces the stored one; an identical replay touches nothing, so replay
  idempotence holds.
- **Values.** Values stay `double precision`, as in Prometheus and most
  time-series stores; aggregation over float64 is fast and adequate for
  counts, rates and durations. Currency metrics are emitted in integer minor
  units, named by ISO 4217 code plus `_minor` (for example `EUR_minor`).
  Integers are exact in float64 up to 2^53.
- **Granularity.** Metric definitions declare `granularity`: `day`, `hour`
  or `instant`. Bucketed values are stamped at the bucket start in UTC; a
  daily value for the provider's reporting date D is stamped `D T00:00:00Z`.
  The query layer (milestone 04) aggregates according to granularity and
  metric kind.
- **Backfill.** Connectors declare `backfillDays`, required when
  `supportsBackfill` is true, instead of the engine's fixed 90 days.
- **Partitioning** stays off. The key now permits range partitioning on
  `source_timestamp` when volume justifies it (architecture: "Deferred
  infrastructure").

These are breaking SDK changes. `SDK_VERSION` moves to 0.2.0, and connectors
declare `sdkVersion: "^0.2.0"`.

## Consequences

- Migration 0012 derives `series_key` for existing rows and keeps the most
  recently ingested value where rows collapse onto one key.
- An observation's API identity is `(metricKey, seriesKey, sourceTimestamp)`
  within its connection; the API no longer returns a row id.
- One statement may not update a key twice, so the engine deduplicates each
  run by `observationKey()` (the last value wins) before upserting.
