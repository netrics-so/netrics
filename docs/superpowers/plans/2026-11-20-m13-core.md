# Custom API connector core (milestone 13, plan C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workspace member stores a versioned custom API definition (no secrets) and connects it several times; the bundled `custom-api` connector runs each connection's pinned definition through the egress guard with none / API key / bearer / basic / OAuth client credentials / OAuth authorization code, every pagination style, typed field mapping and incremental windows, and emits typed source datasets like any bundled connector.

**Architecture:** The portable definition document and its pure helpers (placeholders, dotted paths, limits, upgrade) live in `@netrics/connector-sdk/custom-api`, the one package both `contracts` and `connectors` may import. The server stores definitions as immutable versions (migration 0085) and pins each connection to one version and one environment. Because a manifest is per connection, `custom-api` is not in the `ConnectorRegistry`: the server resolves every connection-scoped connector through `connectorFor(registry, connection)`, which builds (and caches per version and environment) a `Connector` with an effective manifest from the pinned definition; bundled connectors resolve through the registry as before. Custom OAuth reuses the ADR 0012 tables, token service and callback route with provider id `custom`, whose endpoints come from the pinned definition and whose client ID and secret come from the connection's credential envelope.

**Tech Stack:** TypeScript, zod 4, Fastify, drizzle-orm + PostgreSQL (RLS), undici (egress), vitest, generated OpenAPI.

**Spec:** `docs/superpowers/specs/2026-11-20-custom-api-connector-design.md` (sections 1–5, 10, 11 and the auth table of section 3). Cross-plan names: `docs/superpowers/plans/2026-11-20-m13-overview.md`, "Cross-plan contracts". Where silent: ADR 0012 (OAuth), ADR 0022/0023/0024 (datasets, staging), `#758` (cursor and `nextFrom`).

## Deviations from the first overview draft (already recorded in the overview during reconciliation)

1. **Connections created from a definition move from C-G2 to C-G3.** Creating a connection must run the connector check, and a connection without a runnable connector would be scheduled and fail as "no connector registered" on every deploy between C-G2 and C-G3 (every `main` commit deploys). C-G2 ships the tables, columns, database helpers and definition CRUD; C-G3 ships `POST …/definitions/:definitionId/connections`.
2. **`custom-api` is not registered in `ConnectorRegistry`.** Its manifest differs per connection; a static registry entry would make every forgotten `registry.get(connectorId)` silently use a wrong manifest. Migration 0085 inserts the `connectors` catalog row (`'custom-api'`) the foreign key needs; `registry.get("custom-api")` stays `undefined`, so a missed call site fails loudly ("no connector registered").
3. **`oauth_authorizations.purpose` gains `'authorize'`** (C-G4, migration 0086): a custom OAuth connection exists (holding client ID and secret) before its first grant, which neither `connect` (no connection yet) nor `reauthorize` (has a grant) describes.
4. **C-G4 runs after B-G1.** The builder needs OAuth before a definition is saved, so C-G4 reads every custom OAuth connection's definition through B-G1's `loadConnectionCustomApiDefinition` (pinned definition, or the draft's unsaved one). Drafts and that loader belong to B-G1 (migration 0088 adds `connections.status`); C-G4 consumes them.

## Review Focus

1. **A value that does not fit its field type** (`"n/a"` in an integer field, `"31.12.2024"` for a field declared `iso`, a number with more decimals than the field's scale). Expected: a nullable field becomes `null`, a non-nullable or key field skips the record; the run continues, and a log line per page counts skipped records and nulled values per field id (never the value). Test in Task 10 (`"nulls an unparseable nullable value and skips a record whose key does not parse"`).
2. **A next-page link on another host, or a cursor that repeats.** Expected: an off-host next URL fails the run with the fixed `nextUrlOffHost` message and no request is sent to that host; a cursor equal to the previous one ends the stream (no endless loop). Test in Task 10 and Task 13 (real egress).
3. **The API echoes a secret** (the API key in a 400 body, the key as a query parameter in the failing URL, a basic-auth header). Expected: errors, check messages and logs contain `[redacted]`, never the key, the password or the base64 basic value. Test in Task 9 and Task 13.
4. **Date windows in a non-UTC time zone across a DST change** (`Europe/Berlin`, window 2024-03-30 … 2024-04-01, step 1 day). Expected: contiguous, non-overlapping dates; `window.start`/`window.end` render the calendar dates; unix formats render the zone's midnight instants. Test in Task 11.
5. **A safety limit hit in a `snapshot` stream** (the fixture's endless cursor). Expected: the run ends with error class `budget`, already stored snapshot rows stay (no deletion is inferred from the partial refresh), and the next run starts the stream again. Test in Task 13.

export class DataPathError extends Error {} // message never contains the input beyond 40 chars
export const DATA_PATH_MAX_SEGMENTS = 32;
/** "" → [] (the root). Grammar: segment ("." segment)*, segment = name ("[" index "]")* | '["' quoted '"]'. */
export function parseDataPath(path: string): DataPathSegment[];
/** Canonical form; keys outside [A-Za-z0-9_$-] are quoted: data["first name"][0]. parse(format(x)) === x. */
export function formatDataPath(segments: readonly DataPathSegment[]): string;

  segments: readonly DataPathSegment[],

  template: string,
  values: Readonly<Record<string, string>>,

): string;

- Cross-field rules (each adds an issue with `params: { code }`):
  - Every placeholder in `request.path`, `request.query` values and `request.headers` values names a non-secret variable, a `window.*` name (only when `window.type !== "none"`) or a `page.*` name provided by the pagination type (`page.number`: page_number; `page.offset`/`page.size`: offset or page_number with size; `page.cursor`: cursor). Secret variables only in `auth.headers` values (`placeholder_secret_outside_auth`); `auth.headers` is not allowed on OAuth types (`oauth_secret_variable`).
  - Header names are RFC 7230 tokens; `request.headers` and `auth.headers` may not set `authorization`, `proxy-authorization`, `cookie`, `host`, `content-length`, `transfer-encoding`, `connection` (case-insensitive) (`header_forbidden`). `api_key` with `placement: "header"` may not use those names either.
  - Pagination params must not equal a `request.query` key or the `api_key` query name (`pagination_param_clash`).
  - `authorizeParams` may not set `response_type`, `client_id`, `redirect_uri`, `scope`, `state`, `code_challenge`, `code_challenge_method`, `nonce` (`oauth_param_reserved`).
  - Mirrors of `sourceDatasetSchema` so every valid stream yields a valid dataset: unique field ids; key fields exist, are not nullable and not `json`; `reportingField` exists, is not nullable, is `date` or `timestamp`; `replace_window` needs `reportingField` and a window (`mode_window`); `snapshot` needs `window.type === "none"` (`mode_window`); money and scale rules; `personal` needs `retentionDays` (`personal_retention`).
  - `role: "image"` only on `string` fields (`field_role_type`); a stream with an `image` field needs a `reportingField` (I-G1 picks the newest N by it) (`image_stream_needs_reporting_field`); `format` only on `date`/`timestamp` fields, and the `dd.MM.yyyy`-style formats only on `date` (`field_format_type`).
  - Unique ids among environments, variables, streams (`duplicate_id`); serialized document ≤ `documentBytes` (`document_too_large`).

Connector behaviour:

- `check`: one request: first stream, first page, its last chunk of a one-day incremental window (or no window). 401 → `{ ok: false, message: unauthorized }`, 403 → `forbidden`, host mismatch → `hostChanged`, not JSON → `notJson`; 2xx with valid JSON → `{ ok: true }`; 429 with `Retry-After` → throw `RateLimitedError`; other statuses → throw `Error("HTTP <status> from <redactedUrl>")`.
- `discover`: `[]`.
- `sync`: exactly one HTTP request per call. No/undecodable cursor → stream 0, chunk 0, first page, run counters 0, `startedAt = now`. Before the request: `run.pages ≥ pagesPerRun` → throw `CustomApiLimitError(pageLimit)`; `run.records ≥ recordsPerRun` → `recordLimit`; elapsed ≥ `runDurationMs` → `durationLimit`. Response: 401/403 → throw `CustomApiAuthError`; 429 → `RateLimitedError`; non-2xx → `Error("HTTP <status> from <redactedUrl>")`; `jsonTooDeep` or parse failure → `CustomApiResponseError(notJson)`. Records → `mapRecords`; for `replace_window` rows outside the chunk are dropped. Rows are cut into dataset pages of ≤ 1,000 rows and ≤ 1 MiB (`DATASET_LIMITS`), keys `p<pageIndex>`, chained by `previousPageKey`; `refreshKey` = `sha256(stream key, chunk, request.from, request.to)` fixed at the refresh's first page; `complete: true` on the last dataset page of the refresh (refresh = the chunk for upsert/append/replace_window; the whole stream for snapshot); `window` set for `replace_window` (chunk dates). An empty refresh still emits one empty complete page. `runtime.log?.warn("records skipped", { stream, skipped, …nulled per field id })` when counts > 0. The final call returns `done: true`, `receivedDatasets` = every stream key, `nextFrom` = `nextFromFor(...)` (incremental only).
- Never puts a response body, header value or credential into an error or log.
