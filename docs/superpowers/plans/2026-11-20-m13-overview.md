# Milestone 13 custom API connector — plan overview

Spec: [docs/superpowers/specs/2026-11-20-custom-api-connector-design.md](../specs/2026-11-20-custom-api-connector-design.md).
Four plans implement it; each group below is one GitHub issue and one PR.
Execution: subagent-driven, one implementer per group in its own worktree,
fresh reviewer, merge on green. Groups marked parallel may run together.

| Plan | File                           | Groups      |
| ---- | ------------------------------ | ----------- |
| F    | `2026-11-20-m13-foundation.md` | F-G1, F-G2  |
| C    | `2026-11-20-m13-core.md`       | C-G1 … C-G4 |
| B    | `2026-11-20-m13-builder.md`    | B-G1 … B-G3 |
| I    | `2026-11-20-m13-images.md`     | I-G1 … I-G3 |

## Build order

1. **F-G1** dataset contract v1 (ADR 0026) + field role `image` · **F-G2**
   egress hardening + SSRF suite · **C-G1** definition schema (all parallel).
2. **C-G2** definitions persistence + API (migration 0085; needs C-G1).
3. **C-G3** `custom-api` connector: auth none/API key/bearer/basic,
   pagination, windows, fixture server, `connectorFor`, connections from a
   definition, ADR 0027 (needs F-G1, F-G2, C-G1, C-G2).
4. In parallel after C-G3: **B-G1** draft connections + test request API
   (migration 0087) · **I-G1** image ingestion (migration 0086; uses C-G3's
   `connectorFor`, `customApiEnvironment`, `applyCustomApiAuth`).
5. After B-G1, in parallel: **C-G4** custom OAuth (client credentials,
   authorization code; the next free migration number). It reads drafts through B-G1's
   `loadConnectionCustomApiDefinition`, so OAuth works before a definition is
   saved. · **B-G2** builder UI. B-G2's Login step ships the OAuth panel
   (Task 8), which calls C-G4's routes: B-G2 may start with C-G4 but merges
   after it.
6. **B-G3** versions, export/import, connection updates (after B-G2).
7. **I-G2** latest-items widget: contracts, query, device payload, web,
   kiosk (migration 0088; after I-G1; independent of B and C-G4) →
   **I-G3** netrics TV rendering + offline cache (after I-G2 is deployed).
8. Exit gate run (spec "Exit gate"), hosted and self-hosted, with the owner.

Critical path: C-G1 → C-G2 → C-G3 → B-G1 → C-G4 / B-G2 → B-G3. I-G1 → I-G2 →
I-G3 runs beside it from step 4.

## Cross-plan contracts

Names every plan uses. A plan that needs to deviate updates this file in its PR.

- **Connector id:** `custom-api`. Bundled in `packages/connectors/src/custom-api/`
  (subpath `@netrics/connectors/custom-api`).
- **Definition schema (C-G1):** `packages/connector-sdk/src/custom-api/definition.ts`
  (subpath `@netrics/connector-sdk/custom-api`; the only package both
  `contracts` and `connectors` may import; `PACKAGE_LAYERS`). Exports
  `customApiDefinitionSchema`, `CustomApiDefinition`,
  `CUSTOM_API_SCHEMA_VERSION = 1`,
  `upgradeCustomApiDefinition(raw: unknown): CustomApiDefinition`,
  `CustomApiDefinitionError`, `CUSTOM_API_LIMITS`, `customApiIssues`, and the
  strict sub-schemas `customApiEnvironmentSchema`, `customApiVariableSchema`,
  `customApiAuthSchema`, `customApiFieldSchema`, `customApiPaginationSchema`,
  `customApiWindowSchema`, `customApiStreamSchema` (B-G1 builds its draft
  schema from them). Images live in the document's `images?: { hosts,
newestItems }` block (default newest 12, max 50); a stream with an `image`
  field needs a `reportingField` (issue `image_stream_needs_reporting_field`).
  Field `format` values: `iso`, `unix_seconds`, `unix_millis`, `yyyy-MM-dd`,
  `dd.MM.yyyy`, `MM/dd/yyyy`, `dd/MM/yyyy`, `yyyyMMdd`. Marked internal (not
  part of the SDK published in 12).
- **Dataset field role (F-G1):** `role?: "image"` on `datasetFieldSchema`,
  SDK version `0.2.17`; preparations keep it on select/rename/filter/append/
  join pass-through and drop it on calculated or grouped outputs (group keys
  keep it). Dataset contract v1 is ADR 0026.
- **Egress (F-G2):** `createEgressFetch(options: EgressOptions)` gains
  `pinDns` (default `true`), `redirects: "same-host" | "allowlist"`,
  `maxDecompressedBytes`, `requestTimeoutMs`, `allowPrivateHosts?: readonly
string[]`, and the tests-only `tlsCa?: string`. `ExecuteOptions.egress`
  picks `lookup`, `allowPrivateAddresses`, `allowInsecureHttp`, `tlsCa`,
  `allowPrivateHosts`, `redirects`, `requestTimeoutMs`, `maxResponseBytes`,
  `maxDecompressedBytes`, `pinDns`. Self-host setting
  `NETRICS_CUSTOM_API_PRIVATE_HOSTS` → `config.customApiPrivateHosts`, never
  set on hosted. `EgressTimeoutError` is retryable. C-G3's
  `customApiEgress(privateHosts, base?)` is the one place the custom-api
  values (same-host redirects, 10 MiB / 50 MiB / 30 s) are set.
- **Tables (C-G2, migration 0085):** `custom_api_definitions` (workspace,
  project, name, `current_version` integer, archived_at, created_by),
  `custom_api_definition_versions` (immutable JSON `document`,
  `document_sha256`, `dataset_versions`, `created_by`, created_at);
  `connections` gains `custom_api_definition_version_id` and
  `custom_api_environment_id`, both null for bundled connectors and for
  drafts (check `connections_custom_api_pin`, relaxed for drafts by 0088).
  Credentials stay in the existing envelope.
- **Definitions API (C-G2):** `/v1/workspaces/:workspaceId/custom-api/definitions`
  GET list, POST create; `/:definitionId` GET, PATCH (project);
  `/:definitionId/versions` POST `{ baseVersion: number, document }` (409
  `custom_api_definition_stale`); `/:definitionId/archive` POST. Responses
  `customApiDefinitionResponseSchema` (`{ definition: summary + document +
datasetVersions }`). Server service `createCustomApiService` (`list`, `get`,
  `create`, `createVersion`, `update`, `archive`).
- **Connector resolution (C-G3):** `custom-api` is **not** registered in
  `ConnectorRegistry`; migration 0085 inserts only its `connectors` catalog
  row. Every connection-scoped lookup goes through
  `connectorFor(registry, connection)` (bundled → registry; custom-api →
  built from the pinned definition, cached per version and environment).
  `GET /connectors` does not list it; the generic create/batch/preview routes
  answer 400 `custom_api_requires_definition`.
- **Connections from a definition (C-G3, not C-G2):**
  `POST /v1/workspaces/:workspaceId/custom-api/definitions/:definitionId/connections`
  (`createCustomApiConnectionRequestSchema`); connection `config` = the
  non-secret variable values; envelope `{ host, …credentials, variables:
secretVariables }`; `connectionSchema.customApi = { definitionId, version,
environmentId, environmentName }` (B-G3 adds `currentVersion`,
  `updateAvailable`). Instance limits `NETRICS_CUSTOM_API_MAX_DEFINITIONS`,
  `_MAX_STREAMS`, `_MAX_CONNECTIONS`, `_MIN_REFRESH_MINUTES`.
- **Draft connections (B-G1, migration 0088):** `connections.status = 'draft'`
  (`'active'` otherwise), connector `custom-api`, no pin; the unsaved
  definition, environment and non-secret values live in
  `connections.config.draft`; secrets in the envelope in the shape C stores
  for the auth type. Never scheduled, hidden from every connection path,
  deleted by `prune_draft_connections` after 24 h untouched. Read through
  `loadConnectionCustomApiDefinition(tx, workspaceId, connectionId)`
  (B-G1, `apps/server/src/custom-api/load-definition.ts`), which answers the
  pinned definition for active connections and the stored draft definition
  for drafts. Promote: `POST …/drafts/:draftId/promote { definitionId,
version, name, projectId }`. Test requests: at most 30 per workspace per
  minute (429 `custom_api_test_rate_limited`, `Retry-After`).
- **Custom OAuth (C-G4, the next free migration number):** provider id `custom`; endpoints
  from the connection's definition read through
  `loadConnectionCustomApiDefinition` (pinned or draft); client ID/secret in
  the credential envelope (`CustomOAuthCredentials`); `account_sub`
  generated (`custom:<uuid>`); `oauth_authorizations.purpose` adds
  `'authorize'` (a connection that holds client credentials before its first
  grant).
- **Images (I-G1, migration 0086; reserved as 0087, renumbered so numbers
  stay contiguous on `main`):** `workspace_images.origin = 'custom_api'`;
  tables `custom_api_item_images (workspace_id, url_sha256, image_id,
last_seen_at)` and `custom_api_stream_images (connection_id, stream_key,
stored, unchanged, skipped, skipped_reasons)`; quota env
  `NETRICS_CUSTOM_API_IMAGE_QUOTA_COUNT` (default `500`) and
  `NETRICS_CUSTOM_API_IMAGE_QUOTA_MIB` (default `200`); per image max 2 MiB;
  newest N from `definition.images.newestItems` (default 12, max 50). Image
  hosts join the effective manifest's `outboundDomains`; auth only on the
  environment host.
- **Widget (I-G2, migration 0088):** widget type `items`, bound to a
  **published model** (like `measure`) with an image dimension; device
  payload adds it behind `?features=items`; older TV apps and kiosks get a
  text placeholder. A device may fetch a `custom_api` image only when the
  image is referenced by its own current payload.
- **Clients:** the TV app is `apps/netrics-tv` (NetricsKit/NetricsUI); the
  "renderer" is the web kiosk (`DeviceWidgetView`); `apps/renderer` is
  parked.
- **ADRs:** 0026 dataset contract v1 (F-G1); 0027 custom API connector
  (C-G3, OAuth section C-G4).
- **Migrations:** 0085 (C-G2), 0086 (I-G1), 0087 (B-G1), 0088 (I-G2);
  C-G4 takes the next free number when it merges. Numbers stay
  contiguous on `main`: drizzle applies migrations in journal order and
  skips one whose timestamp is older than the last applied, so a group
  whose number is taken when it merges regenerates its migration as the
  next free number on top of `main` and updates the references in its PR.
  Migration tests find migrations by tag suffix, not number.
- **Fixture server:** `packages/connectors/src/custom-api/testing/fixture-server.ts`
  (C-G3), `startCustomApiFixtureServer(options?: { port?; tls? })`, secrets in
  `FIXTURE_SECRETS`, requests recorded with their `host`. Extended by C-G4
  (OAuth endpoints), B-G1 (builder routes) and I-G1 (images). Binds to
  127.0.0.1; tests reach it with `allowPrivateHosts: ["127.0.0.1"]`. Tests
  that store a definition through the API (schema demands https) start it
  with `tls: true` and pass its `ca` as egress `tlsCa`.
