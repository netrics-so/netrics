# Custom API images and the latest-items widget (milestone 13, plan I) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a custom API stream syncs, netrics copies the images of its newest records into the workspace (validated, metadata stripped, own quota). A new `items` widget shows the newest items of a published model as a grid or one at a time, on the web (Studio, kiosk, scroll view) and on netrics TV, with images loaded only from netrics and cached for offline playback.

**Architecture:** Ingestion is a best-effort step after a succeeded sync, like resource icons (`apps/server/src/images/resource-icons.ts`). The server reads the newest N image URLs of each image stream from the stored dataset. The bundled `custom-api` connector downloads them through the egress guard, with auth only when the image host is the API host. The server validates the bytes with `sanitizeImage` and stores them as `workspace_images` of origin `custom_api`. A lookup table maps `(workspace, sha256(url))` to the stored image. The widget binds to a published model, like the `measure` widget, so dashboard filters, exclusions, slide scopes and screen scopes apply through `dashboardModelQuery`. It queries the model grouped by the time, image, title and subtitle dimensions, newest first, and resolves each URL to a stored image reference. Clients never receive the source URL. Device payloads carry item image references in `images`; screens without the `items` feature get a text placeholder instead.

**Tech Stack:** TypeScript, Fastify, drizzle-orm + PostgreSQL (RLS), zod contracts + generated OpenAPI, Next.js web app, vitest, Playwright; Swift 6 / SwiftUI (NetricsKit, NetricsUI) for netrics TV.

**Spec:** `docs/superpowers/specs/2026-11-20-custom-api-connector-design.md`, section 8 (images and the latest-items widget), plus anti-goals, constraints and exit gate 4. Cross-plan names: `docs/superpowers/plans/2026-11-20-m13-overview.md`. Image rules: `docs/decisions/0015-dashboard-studio.md`, section 5.

## Global Constraints

- Images are copied into netrics (owner's choice A). Web and TV load them only from netrics: `GET /v1/workspaces/:w/images/:id/content?v=<sha256>` and `GET /v1/device/images/:id?v=<sha256>`. The source URL never reaches a client, payload, log or error.
- Raster only: PNG, JPEG, WebP. Metadata is stripped without re-encoding (`sanitizeImage`). No new native image library. At most 4096 × 4096 px and 16.7 megapixels (existing `IMAGE_MAX_SIDE` / `IMAGE_MAX_PIXELS`).
- At most **2 MiB** (`2_097_152` bytes) per `custom_api` image; uploads stay 1 MiB. Larger images are skipped and counted.
- Origin `custom_api` with its own workspace quota: default **500 images, 200 MiB**, instance settings, not counted against uploads (100 / 50 MiB). Uploads and resource icons are not counted against it.
- Newest N per image stream by the stream's reporting/time field: default **12**, max **50**.
- Stored images are keyed by **workspace and URL hash** (`sha256` of the exact URL string, lower-case hex), never by record or connection. A URL already stored is not downloaded again.
- Images no longer among any stream's newest N are deleted after a grace period: `CUSTOM_API_IMAGE_GRACE_DAYS = 7`, measured from `last_seen_at`.
- A failed or skipped image never fails the sync. The item shows without its image, and the stream shows a count of skipped images.
- Downloads go only through the egress guard (`createEgressFetch`), only to the definition's image hosts (default: the API host). Image requests carry auth **only** when the image host equals the connection's environment host. Redirects stay on the same host.
- Tenant isolation twice: RLS (`app.workspace_id`) on every new table, and an explicit `workspace_id` predicate in every new query.
- Device payloads stay backward compatible: the `items` widget is sent only to clients that ask with `?features=items`. Every other schema 2/3 client gets a `text` placeholder in its place, and none of the widget's item images. The payload carries image references, not bytes.
- Every new UI string in English and German (informal "du"), in the existing catalogs: `apps/web/src/messages/{studio,screen,sources,api-errors}/{en,de}.ts`, `packages/domain/src/i18n/shared/{en,de}.ts` (server-worded labels), `apps/netrics-tv/NetricsKit/Sources/NetricsUI/Resources/Localizable.xcstrings` (TV).
- Definition of done (CLAUDE.md), per group: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test`. Also `pnpm openapi:check` after route or contract changes (`pnpm openapi` regenerates). Migrations come from `pnpm db:generate`, hand-edited where unsafe, and are tried on data in the previous shape. Extend `pnpm e2e` when a UI flow changes. One issue per PR with `Closes #N`; squash-merge on green CI. TV group: `swift test` and the `xcodebuild` builds from `apps/netrics-tv/README.md`.
- Tests needing PostgreSQL: `NETRICS_TEST_ADMIN_URL=postgres://netrics:netrics@localhost:5433/postgres pnpm vitest run <file>`. Pure tests: `pnpm vitest run <file>`.
- Private details of the owner's first-party service (hosts, accounts, tokens) never enter this repository, its fixtures or its tests.

## Review Focus

1. **Expiring signed URLs** (S3-style `?X-Amz-Signature=…` that changes every sync, same bytes). Expected: every new URL gets a lookup row, but the bytes are stored once. A `custom_api` image with the same content `sha256` is reused, so storage and quota do not grow per sync. Test in Task 4 (`reuses the stored image when a new URL returns the same bytes`).
2. **Two connections (or two streams) sync the same URL at the same time.** Expected: one lookup row, no unique-violation failure, and at most one orphaned image, which garbage collection removes. Test in Task 2 (`upsertItemImage keeps one row under concurrent upserts`) and Task 5 (`deletes custom_api images without a lookup row`).
3. **An image host that is the API host but answers with a redirect to another host** (CDN offload). Expected: the request is refused, the item is counted as `fetch_failed`, and the credentials are never sent to the other host. Test in Task 3 (`does not follow a redirect to another host with credentials`).
4. **A model that filters or joins the stream, so the widget's newest items differ from the stream's newest N** (an older item becomes visible after a filter). Expected: the item shows with `image: null`; no download at query time, and no error. Test in Task 8 (`shows items outside the stored newest N without an image`).
5. **An older netrics TV (0.3.x) or kiosk on a dashboard with an items widget.** Expected: a text placeholder in the widget's place, none of the items' images in `images`, and an ETag distinct from the full form. Test in Task 9 (`older clients get a placeholder and no item images`).
