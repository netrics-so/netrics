# Milestone 13.1 — Developer sources

## Outcome

A developer who runs several products on Railway, Vercel and Hetzner, with
apps in the App Store and Google Play, PostHog analytics and Google Search
Console, sees all of it on one Apple TV dashboard. Next to the product
numbers netrics already shows (downloads, revenue, ratings, visitors,
search), every project's slide answers the operational questions:

- Is it up? Service and server state, plus HTTP health checks.
- What shipped? The latest deploy per service and whether it succeeded.
- What does it cost? Spend or usage this month per provider, where the
  provider exposes it.
- Who uses it? Product analytics from PostHog.

These are combined with the data layer of milestone 11: deploys, costs and
analytics are prepared, related to the workspace's projects and summed or
filtered per project, while single values (a service's state) come straight
from the source.

The target is the hosted service and a netrics TV TestFlight build.
GitHub milestone "13.1 Developer sources".

## Dependencies

- Milestone 11: preparations, relationships, measures, dashboard filters.
- Milestone 11.2: slide scope, freshness on every number.
- Milestone 13: the custom API connector, its egress and credential rules.
- Milestone 09.1: every new string in English and German.

## In scope

- Read-only POST and GraphQL in the custom API connector
  ([ADR 0030](../decisions/0030-custom-api-read-only-post.md)), in the SDK,
  the connector and the builder
- Native connectors: Railway (new), Vercel deployments (added to the
  existing Vercel connector), Hetzner Cloud (new), PostHog (new)
- HTTP health checks: a connection that requests configured URLs on a short
  interval and records status code and response time
- A status widget: the current state of a service, server, deploy or check
  as up, down, building or failed, on web screens and in netrics TV
- A "Developer Portfolio" template: an overview slide (everything that is
  down or failed, deploys today, spend this month) and one slide per
  project combining product and operations numbers
- A netrics TV TestFlight build with the status widget

## Out of scope

- Alerts on any of these numbers (milestone 14)
- Logs, traces and error tracking (Sentry and similar)
- Changing anything at a provider: restarting, redeploying, scaling
- Costs a provider does not expose through its API; the connector documents
  what it can and cannot read
- Health checks from several regions, or checks of private-network URLs on
  the hosted service
- Self-hosted acceptance (stays with the earlier gates)

## Questions to settle in the issues

The cost and usage APIs differ per provider and must be checked against
each provider's current API documentation before a connector issue is
designed:

- Railway: usage and estimated cost per project through the public
  GraphQL API.
- Vercel: whether usage or billing data is readable with a team token.
- Hetzner Cloud: the API has no invoices; a monthly estimate from the
  project's servers and the public price list is the likely answer.
- PostHog: personal API keys are scoped per project and region (US, EU or
  self-hosted host).

next free migration number when they are implemented.

## Exit gate

#877: on the hosted service, a physical Apple TV with the TestFlight build shows
the Developer Portfolio for the owner's real accounts: every Railway
service and Vercel project with its state and latest deploy, every Hetzner
server with its state, the month's spend where the provider exposes it,
PostHog users per project, and the health checks. Stopping a test service
or failing a test deploy shows on the TV within one sync interval plus one
TV refresh interval (faster delivery to the TV is #789 in milestone 13.2). One internal GraphQL or
query API is connected through the custom API builder without code.
