# Milestone 10.1 — netrics TV on iPad and iPhone

## Outcome

The viewer app "netrics TV" runs on Apple TV, iPad and iPhone as one App
Store product with universal purchase. An iPad or iPhone pairs with a
netrics server by code, exactly like an Apple TV, and shows the workspace
dashboard assigned to it: screen view on iPad in any orientation and window
size, scroll view on iPhone in portrait and screen view in landscape. There
is no sign-in in the app; administration stays on the web until the later
admin app "netrics".

Design: [ADR 0021](../decisions/0021-netrics-tv-on-ipad-and-iphone.md)
(netrics TV on iPad and iPhone). GitHub milestone "10.1 netrics TV on iPad
and iPhone" (created after the owner has read this plan).

## Numbering

Milestones 11 to 17 are taken and form the v1 sequence. Decimals mark work
that runs beside a numbered milestone without renumbering the sequence, as
03.1–03.3 and 09.1–09.3 do. 10.1 is the next free decimal at the current
position (milestone 10, Apple Ads, is in progress), and it sits before 11, so
the touch apps arrive before the v1 hardening, not after it. It is not 06.1:
milestone 06's exit gate is still open (#58), and a 06.x would read as part of
it. Like 09.x and 10, it runs beside the open exit gates of 06 to 09.3; the
rule "complete one milestone before opening the next" is relaxed for it.

## Architectural purpose

The Apple TV app becomes a product on three platforms without a second
code base. NetricsKit (protocol, formats, reflow, formatting; no UI) gains
iOS; the platform-neutral SwiftUI rendering moves into a shared `NetricsUI`
library; a second app target builds the universal iPhone and iPad app with
the same bundle identifier, so App Store Connect holds one record with the
tvOS and iOS platforms. The server learns each device's platform, lets a
device revoke itself on unpair, and otherwise serves the same payload (schema 3) it serves to TVs. Everything is built with Xcode 27 and the 27 SDKs.

## In scope

- Xcode 27 toolchain, deployment targets iOS and iPadOS 27 and tvOS 26, CI
  on macOS 26 building both app targets
- `NetricsUI` library shared by both targets; tvOS unchanged in look and
  behaviour after the move
- The universal iOS target "netrics TV" (iPhone and iPad), the tvOS target
  renamed to "netrics TV", the iOS icon from the same sources
- Pairing on iPad and iPhone: server choice, code, QR code, share link, open
  the approval page, copy code; settings; unpair that revokes on the server
- Server: device platform (pairing body, heartbeat, record, defaults,
  device list), rotation ignored for touch devices, device self-revoke
- iPad screen view in every orientation and window size (Split View, Slide
  Over, Stage Manager)
- iPhone scroll view in portrait and screen view in landscape, with the
  device's display mode setting
- Touch: swipe between slides, tap for a widget detail sheet, chrome with
  pause and settings, the same as VoiceOver actions
- Idle timer in screen view; a guide for wall and desk iPads (Guided Access,
  Single App Mode)
- Foreground and background lifecycle, offline start from the cache
- Demo mode for App Review and first users, on all three platforms
- Privacy manifest, export compliance, VoiceOver and Dynamic Type
- App Store Connect record with universal purchase, TestFlight, App Review
  (owner)

## Out of scope

- The admin app "netrics", personal sign-in, passkeys, workspace switching,
  approving a code inside any app
- Apple Watch
- Home Screen and Lock Screen widgets, the snapshot endpoint and background
  refresh (a follow-up; the App Group and Keychain access group are prepared)
- Universal links for `netrics.tv/<CODE>`
- Managed app configuration and Autonomous Single App Mode for MDM fleets
- The iPad app on Mac and on Apple Vision Pro
- Android
- New widget types or payload schemas

### T3 (#406) — Server: device platform, defaults by platform, device list

- **Scope:** migration: `device_pairings.platform` and `devices.platform`
  (`tvos`, `ipados`, `ios`, `web`, null), checked. `POST /v1/device/pairings`
  accepts an optional body `{ platform }` (no body stays valid); approval
  copies it to the device; the heartbeat accepts an optional `platform` and
  fills a null one. The approve form prefills the name by platform; approval
  sets `display_mode` to `scroll` for `ios`, else `screen`. The web hides
  rotation for `ios` and `ipados`; the screens list shows the platform and
  "last opened" instead of offline for them. The tvOS app and the browser
  kiosk report their platform. Contracts, OpenAPI, English and German.
- **Acceptance:** old clients (no body, no field) pair and heartbeat
  unchanged; the platform never changes access; RLS and `workspace_id`
  predicates on every query, with cross-workspace tests; migration tried on
  data in the previous shape (paired TVs and kiosks).
- **Depends on:** T1

### T4 (#407) — Server: device self-revoke on unpair

- **Scope:** `POST /v1/device/me/revoke` with the device access token
  revokes the device and all its tokens in one transaction and audits
  `device.revoked` with the device as actor. `DeviceClient.unpair()` calls it
  first, then clears local state; a network error or 404 (older server)
  keeps today's local unpair. The kiosk adopts it too.
- **Acceptance:** after unpair the web list shows the device revoked; a
  later request with its tokens gets 401; an older server still unpairs
  locally; NetricsKit tests cover the three cases.
- **Depends on:** T1

## Security invariants

- No user credential ever reaches the app. Approval happens on the web, in
  the browser's own session.
- Device credentials stay in the Keychain, this device only, after first
  unlock; they are not in backups and are never shared with another device.
- The self-reported platform steers defaults and labels only, never access.
- A device can revoke only itself; the self-revoke needs its access token.
- Plain HTTP only to local-network hosts, self-signed certificates only
  pinned, as on tvOS (ADR 0010).
- The demo mode sends nothing and holds no credential.
- The repository holds no Apple team ID, provisioning or App Store Connect
  detail.

## Verification

- An iPad and an iPhone pair, show the dashboard, survive revocation and
  re-pair, exactly as an Apple TV does.
- Turning an iPad or iPhone, and resizing an iPad window, re-lays out
  instantly and offline.
- Unpairing in the app revokes the device on the server.
- Released Apple TV builds and older servers keep working.
- Both app targets build in CI on Xcode 27.

## Exit gate

On a real iPad, a real iPhone and a physical Apple TV, with TestFlight
builds from the one universal record, hosted and self-hosted (T17):

1. Pair the iPad with netrics cloud, approving on another device's browser;
   pair the iPhone with a self-hosted server on the local network, approving
   in Safari on the same iPhone (local network prompt accepted).
2. iPad: landscape and portrait, Split View at one third and half, a Stage
   Manager window resized to its smallest; slides rotate, swipe and tap work,
   the screen stays on. Run Guided Access from the guide for an hour; an OLED
   iPad shows no image retention.
3. iPhone: scroll view in portrait, screen view in landscape; switch the
   device to "Screen view" on the web and see portrait screen view.
4. Change the assigned dashboard on the web; all three devices follow
   within one poll.
5. Turn on airplane mode, relaunch: the cached dashboard shows with the
   offline header; turn it off and the dashboard refreshes.
6. Unpair the iPhone in the app: it shows revoked on the web. Revoke the
   iPad on the web: it shows a new code.
7. Walk the iPhone app with VoiceOver and at the largest text size.
8. The Apple TV, now "netrics TV", behaves as before, with demo mode and
   the server-side unpair.
9. Both platforms pass App Review (T16).
