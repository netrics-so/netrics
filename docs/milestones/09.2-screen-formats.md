# Milestone 09.2 — Screen formats and display modes

## Outcome

Every dashboard works on any screen: landscape TVs, portrait TVs and
signage, ultra-wide monitors, 4:3 and 16:10 screens, tablets in either
orientation, phones, and a desktop browser used as a standby screen. The
user designs once in a primary format; netrics reflows the design for every
other format and the user can arrange any format by hand. Screens show
dashboards in **Display** mode (fits the screen, rotates, no scrolling) or
**Glance** mode (one scrolling page, slides as sections). The Studio
previews every format in a device frame. Existing dashboards and released
tvOS builds keep working unchanged.

Design: [ADR 0017](../decisions/0017-screen-formats-and-display-modes.md).
GitHub milestone "09.2 Screen formats and display modes".

## Dependencies

- Milestone 09 (Dashboard Studio): slides, widgets, `studioLayout`, payload
  schema 2 and the Studio editor this extends.
- Milestone 09.1 (internationalisation): every new string in English and
  German.
- Native mobile apps are **out of scope** (a later milestone); the web
  Glance mode is their base and must work in mobile browsers.

## In scope

- Five format classes (`16x9` 12 × 8, `21x9` 16 × 8, `4x3` 9 × 8, `3x4`
  6 × 10, `9x16` 6 × 14) and size classes; a real screen maps to a format by
  its aspect ratio
- Display on any aspect ratio: fill the screen, stretch at most 4/3, then
  letterbox
- Auto reflow (bands, stacks, shelves, continuation pages) as a pure shared
  function in TypeScript and Swift with test vectors
- Custom layouts per slide and format, hide per format, sync rules with
  review flags, changing the primary format
- Glance mode on the web dashboard page (phones and tablets by default) and
  for kiosk devices set to Glance
- Device settings: rotation (portrait TVs on Apple TV and kiosks) and
  display mode; screen size, format and mode in the heartbeat
- Device payload schema 3; schema 2 projected to the `16x9` layout, schema 1
  unchanged
- Studio: format switcher, device-frame previews, readability warnings per
  format, custom editing
- Readability rules per format; templates without warnings in every format

## Out of scope

- Native iOS and Android apps, and swipeable Glance pages (later, on the
  same domain functions)
- Custom Glance order or per-widget Glance visibility
- Further format classes (16:10, 32:9 as their own grids)
- Portrait-first templates (templates stay `16x9`; they reflow)
- Server-side rendering of formats

## Security invariants

- `dashboard_slide_layouts` and `dashboard_widget_layouts` are under RLS
  with explicit `workspace_id` predicates; composite foreign keys keep every
  placement in the workspace of its widget and slide; cross-workspace tests.
- Heartbeat `screen` values are bounded numbers and enum keys, validated by
  zod; device settings need `devices:update` and are audited.
- Device payloads still contain only the assigned dashboard; custom layouts
  add placements, nothing else.
- No new dependency: frames are CSS, rotation is a transform, Wake Lock and
  `ResizeObserver` are platform APIs.

## Verification

- Every existing dashboard renders on a 16:9 screen exactly as before, on
  web, kiosk and tvOS; released tvOS builds (schema 2) show the `16x9`
  layout.
- The same slide reflows identically on web and tvOS for every format (the
  shared vectors pass on both).
- No format ever shows a widget below its minimum size or a truncated
  label without a Studio warning; overflow appears as continuation pages.
- A widget added to the primary appears in every custom layout, flagged for
  review; deleting it removes it everywhere.
- A kiosk window resized from 16:9 to portrait re-lays out live; a rotation
  change in the TV list reaches the screen within one poll.
- The Glance page has no horizontal scroll at 320 px and is usable with a
  screen reader and the keyboard; the Studio switcher and custom editor are
  usable without a pointer.

## Exit gate

In production, show the **Overview** dashboard and one brand dashboard on a
landscape Apple TV, a portrait screen (Apple TV with rotation 90° and a
browser kiosk on a rotated monitor, auto and custom layouts), a phone in
Glance (iOS Safari and Android Chrome), a tablet in Display (portrait and
landscape) and an ultra-wide browser kiosk. Every title is readable at its
viewing distance, overflow appears as pages, a widget added to the primary
shows up flagged in the custom portrait layout, and the Studio previews
match the real screens (#285).
